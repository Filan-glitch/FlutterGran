# Chalk: five features, five PRs

## Context

Chalk plays a single leg on a phone held in portrait, with no sound, the stock
Flutter icon, and an end-of-leg screen that shows three lines and offers no way
onward. These five changes take it from a working scorer to something you would
choose to use next to a board.

Ground truth that shapes the work, from tracing the code:

- **A "game" in the database is a leg.** `Games` is documented "One leg. The MVP
  plays a single leg per game." Multi-leg is a schema migration, not a field.
- **`winRate` already means leg-win rate**, pinned by tests. Match figures have
  to be added alongside, not folded in.
- **Nothing is responsive.** One `LayoutBuilder` in all of `lib/`, zero
  `MediaQuery`. `Type.score` is a hardcoded 62px and the keypad reserves a fixed
  52px row, so in landscape they compete for height that is not there.
- **The end of a leg navigates nowhere.** `_WinnerPanel` has no buttons.
- **There is no audio at all** — no dependency, no `assets:` key in pubspec.
- **`foldLeg` always starts at seat 0**, with no offset, so alternating who
  throws first needs a real parameter.

## Prerequisites to install

```
sudo apt install gh ffmpeg pipx     # PRs; audio encoding; python app installer
gh auth login
pipx install piper-tts
```

The Piper voice model (~60MB) downloads on first run and is **build-time only** —
it is never shipped.

## 1. `feat/app-icon` — chalk tally

A tally: four chalk strokes struck through by a fifth, chalk-white on the app's
forest ground. Reads at 48px because it is five thick strokes, ties to the name,
and is not another dartboard.

Draw it with Pillow (present, 10.2.0) in a committed script, `tool/make_icon.py`,
so the icon is reproducible rather than a binary someone has to redraw:

- Android legacy: `android/app/src/main/res/mipmap-*/ic_launcher.png`, five densities.
- Android adaptive: `ic_launcher_foreground.png` (strokes, on transparent, inside
  the 66% safe zone) plus a `@color/ic_launcher_background` of `#0E1611`, wired
  through `mipmap-anydpi-v26/ic_launcher.xml`.
- iOS: `ios/Runner/Assets.xcassets/AppIcon.appiconset/Icon-App-1024x1024@1x.png`.

Use `Palette.ground` and `Palette.chalk` from `lib/app/theme.dart` so the icon
and the app cannot drift apart.

## 2. `feat/sound-cues` — commentary and cues

Two kinds of audio, produced two different ways, both offline and unencumbered.

**Spoken, pre-rendered.** The vocabulary is closed: every three-dart total 0-180
plus a handful of phrases. Render once with Piper
(`en_GB-northern_english_male-medium` — the accent darts is commentated in),
encode to OGG with ffmpeg, ship as assets. No TTS engine on the phone, no
per-device variation, no first-call latency. Script: `tool/make_speech.py`,
committed, with the phrase list in it.

Phrases beyond the numbers: `bust`, `no score`, `game shot`, `one hundred and
eighty`, `game on`.

**Cues, synthesised.** A short click when a dart registers, a low buzz on a bust,
a rising two-note chime when a checkout double lands, a fanfare for a 180.
Generated by `tool/make_cues.py` with Python's `wave` module — a few KB each,
tuned exactly, no licensing question. Pitch-separated so a bust and a checkout
are distinguishable across a room.

Wiring:

- `audioplayers` (MIT) with `PlayerMode.lowLatency` for the cues; a dart cue that
  lags is worse than none.
- New `lib/app/audio/sound_controller.dart`, driven by watching `gameProvider` —
  it reacts to state, so nothing in the domain learns about audio and
  `domain_purity_test` stays green.
- Settings: `soundEnabledProvider` and `speechEnabledProvider`, persisted, with a
  toggle row on the setup screen. Both default on, and speech can be silenced
  independently of the cues, since the commentary is what wears out first.

## 3. `feat/multi-leg` — best of N

`Matches` table, schema version 3. `Games` (the legs table) gains a nullable
`matchId` and a `legNumber`; nullable so every existing leg stays valid and
`findResumableGameId` keeps working untouched.

```dart
class Matches extends Table {
  IntColumn get id => integer().autoIncrement()();
  IntColumn get startScore => integer()();
  BoolColumn get doubleOut => boolean().withDefault(const Constant(true))();
  /// Best of this many legs. 1 is a single leg, which is what every existing
  /// game is.
  IntColumn get legsToPlay => integer()();
  DateTimeColumn get startedAt => dateTime().withDefault(currentDateAndTime)();
  DateTimeColumn get finishedAt => dateTime().nullable()();
  IntColumn get winnerPlayerId => integer().nullable().references(Players, #id)();
}
```

Domain: `GameConfig` gains `startingSeat` (default 0). `foldLeg`
(`lib/domain/x01/leg_reducer.dart:16`) currently hardcodes `var playerIndex = 0`
— it takes the offset instead. The default keeps the existing rotation tests
passing unchanged. A new pure `lib/domain/x01/match_state.dart` folds leg
outcomes into legs won, match winner, and who starts next; it must import no
Flutter.

Alternation: leg *n* starts with seat `n % playerCount`. Throwing first is a real
advantage, so a best-of decided by the setup screen is not a match.

Statistics: leave `legsPlayed`/`legsWon`/`winRate` meaning legs — the tests pin
that and it is the right meaning. Add `matchesPlayed`/`matchesWon` alongside.

Setup screen: a best-of choice (1, 3, 5, 7) beside the start score, using the
existing `_ScoreChoice` widget. Scoreboard: a leg tally per player.

## 4. `feat/end-screen` — quiet leg, loud match

Winning a leg shows a compact card: winner, darts thrown, average, the match
tally, and one button to throw the next leg. A best of five has to keep moving.

Winning the match earns the full screen: the winner large, final leg score, then
both players side by side with three-dart average, first-nine, 180s, best
checkout and best leg — everything `computePlayerStats` already returns when
called with the match's legs, which it supports today (it takes any
`Iterable<LegState>` and has no cross-leg state). Actions: rematch with the same
players and format, or back to setup.

Replaces `_WinnerPanel` in `lib/app/screens/game_screen.dart`. A dialog over the
board, not a pushed route — the scoreboard staying visible behind it is what
makes it feel like the end of a game rather than a new screen.

## 5. `feat/responsive-layout` — landscape and tablets

One breakpoint, applied in `game_screen.dart`: below it the current column,
above it scoreboard and turn ledger on the left, keypad on the right. Nothing
shrinks; the score stays readable from the oche, which is the whole point of its
size.

Also needed:

- `Type` in `lib/app/theme.dart` grows a scale factor for large viewports. 62px
  on a 10-inch tablet is small, not large.
- The keypad's fixed `SizedBox(height: 52)` (`dart_keypad.dart:106`) becomes
  proportional, or it survives at full size while the twenty wedge keys are
  crushed.
- `_TurnConfirm` and the end screen need to survive a short viewport — today
  they are unscrollable columns with `Spacer`s and a 62px numeral.
- `_DartSlot`'s fixed `height: 40` and `_TurnLedger`'s `SizedBox(width: 72)`
  become flexible.

`BoardWidget` already handles arbitrary boxes correctly and needs nothing.

## Verification

```
flutter analyze
flutter test
```

Per branch:

- **Icon** — build and install; the launcher shows the tally, legible in the app
  drawer and in the task switcher. Check the adaptive icon under a circular mask.
- **Sound** — play a leg with the fake board: a cue per dart, the total spoken at
  the end of each turn, the bust buzz, the 180 fanfare. Toggle speech off and
  confirm cues survive; toggle sound off and confirm silence.
- **Multi-leg** — new tests: `foldLeg` honours `startingSeat`; the match fold
  calls a best-of-3 at 2-0 and not at 1-1; alternation gives leg 2 to seat 1.
  Play a best of 3 through and confirm the tally and the alternation.
- **End screen** — leg end offers the next leg; match end shows both players'
  figures and rematch returns to a fresh match with the same format.
- **Layout** — rotate mid-leg on the Pixel 9a: no overflow stripes, the score
  stays readable, every key reachable. Widget tests at explicit sizes for phone
  portrait, phone landscape and tablet, in the manner of
  `test/app/board_widget_test.dart`, which already does exactly this for the
  board.

Existing tests that will need updating rather than working around:
`test/widget_test.dart` asserts the AppBar title `'501 · DOUBLE OUT'` and drives
the keypad by text, and `test/domain/player_stats_test.dart` pins the leg
meaning of `legsPlayed`/`legsWon`.
